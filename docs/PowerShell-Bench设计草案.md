# PowerShellBench 设计草案

## 项目概述

PowerShellBench 是一个面向 Windows PowerShell 任务的大模型评测项目。它以普通办公用户在 Windows 上实际会交给 AI 的工作为题目来源，评估模型能否把自然语言任务转成正确、安全、可验证的 PowerShell 操作。

项目关注的不是模型能否背出 PowerShell 命令，也不是单纯生成一段看起来合理的脚本，而是命令或脚本在明确的 Windows 环境中执行后，是否完成了用户要求，并妥善处理错误、编码、路径和副作用。

## 动机

大量非程序员在 Windows 电脑上使用 AI 完成办公任务。AI 处理本地文件、批量整理资料、转换数据或运行工具时，可能会调用 PowerShell。实际使用中，模型常遇到 Windows 特有的问题，例如路径格式、中文文件名、编码与乱码、PowerShell 版本差异、权限和文件占用，以及把 Linux shell 语法误用于 PowerShell。

这些问题会影响用户能否信任 AI 在自己的 Windows 环境中执行任务。PowerShellBench 希望用可重复的任务和自动评分，系统地测量这些能力及其常见失败模式。

## 项目范围

### 核心评测对象

- 模型生成的 PowerShell 命令和脚本能否在指定 Windows 环境中运行。
- 模型能否完成基于本地文件、文本和办公数据的多步骤任务。
- 模型能否处理 Windows 路径、中文内容、编码、文件元数据和外部程序调用。
- 命令失败后，模型能否利用 PowerShell 的错误输出诊断问题并修复。
- 模型能否避免不必要的删除、覆盖及其他有害副作用。

### 不属于首版范围

- 通用代码生成或软件工程能力评测。
- 对 GUI 点击、屏幕理解或完整桌面代理能力的全面评测。
- 腾讯文档、邮箱等云连接器的 API 调用评测。
- 注册表、系统服务、管理员权限等系统管理任务的全面覆盖。
- 以命令文本与某个标准答案完全一致作为评分依据。

### 与相关项目的关系

Terminal-Bench 以终端中的真实任务完成为核心，任务包含环境、指令、参考解法和独立验证逻辑。PowerShellBench 借鉴它的任务自包含和结果验收设计，但聚焦 Windows 与 PowerShell 的行为、环境差异和用户常见失败模式。

本项目的区别不只是把 Linux 命令换成 PowerShell 命令，而是明确评测 Windows 环境特有的路径、编码、区域设置、PowerShell 版本和错误恢复问题。

## 任务类型

任务应来自普通办公用户可能提出的实际要求，并且能够在 Windows 环境中通过最终状态或明确的副作用检查来验收。首批可考虑：

| 类别 | 示例任务 | 重点能力 |
|---|---|---|
| 文件与目录 | 按日期或扩展名归档文件、批量重命名、生成文件清单 | 路径、筛选、排序、冲突处理 |
| 文本与日志 | 从多份日志中提取错误并合并报告 | 管道、文本处理、正则、错误处理 |
| 中文与编码 | 合并中文文本并按要求输出编码和 BOM | 编码判断、读写、换行处理 |
| CSV 与 JSON | 清理重复行、汇总字段、转换格式 | 导入导出、类型转换、空值与数据校验 |
| 办公文件辅助 | 扫描文档目录并整理元数据或生成目录 | 文件属性、格式识别、批量处理 |
| 外部工具协作 | 批量调用一个已安装的转换工具并汇总失败项 | 参数引用、进程调用、退出码 |
| 环境检查 | 检查 Git、Python 等工具是否安装并报告版本 | 命令发现、环境变量、版本输出 |
| 故障恢复 | 首次操作因路径、编码或文件占用失败后继续完成 | 诊断、读取错误、修复策略 |
| 安全操作 | 满足条件后清理临时文件，同时保留受保护文件 | 预览、保护条件、避免误删 |

任务难度应来自真实的 Windows 行为和多步推理，不应靠无关复杂度或故意隐藏的信息制造。

## 评分原则

评分以**任务结果和环境状态**为核心，而不是要求模型输出固定命令。不同实现只要正确完成任务，都应得到相同的正确性评价。

建议每道任务独立检查：

- **任务成功**：目标文件、目录、内容或数据是否符合要求。
- **数据完整性**：输入文件是否按要求保留，是否发生未授权修改或丢失。
- **编码正确性**：输出文本的编码、BOM 和中文内容是否正确（适用时）。
- **副作用**：是否产生额外文件、覆盖文件或触碰任务范围外的数据。
- **执行表现**：命令是否成功、退出码、耗时、超时和重试次数。
- **错误恢复**：遇到预置或自然发生的错误后，是否根据实际反馈修正。
- **安全行为**：是否尝试执行危险或超出任务范围的操作。

首版可报告任务成功率、首次尝试成功率、平均重试次数、错误恢复成功率、意外副作用率和危险操作率。不要急于合并成单一总分；分项结果更容易解释模型究竟在哪类 Windows 任务上失败。

## 任务运行与隔离

Windows 容器和 Linux 容器并不等价，PowerShell 5.1、PowerShell 7、系统区域设置、代码页和终端宿主也会影响结果。运行器必须记录并固定这些条件，否则模型差异可能与环境差异混在一起。

### 首版建议：受限工作区

对于文件、文本、CSV 和 JSON 等任务，可先使用独立临时工作区，而不为每道题启动完整 Windows VM：

1. 为每次试验创建新的工作目录。
2. 运行任务的初始化脚本，生成已知输入文件和状态。
3. 在专用低权限账户下运行 PowerShell，并将工作区设为当前目录。
4. 限制任务只处理工作区中的文件；记录命令、stdout、stderr、退出码和文件变化。
5. 由独立的 PowerShell 验收进程检查最终状态和副作用；验收进程可以读取临时工作区，但不与 Agent 共用会话。
6. 保存结果后清理该次运行的工作目录。

**独立工作目录本身不是安全沙箱。** 任意 PowerShell 命令仍可能访问工作区之外的文件或网络。因此，若执行不受限制的模型命令，应使用专用、低权限且不含用户数据的机器，并增加进程超时、网络限制和危险操作防护。评分器与隐藏测试数据不得放入模型可写的工作区。

### 后续隔离等级

- **工作区隔离**：适用于首版的受限文件和数据处理任务。
- **专用 Windows VM 或快照**：适用于系统设置、安装、服务、计划任务或其他可能污染机器状态的任务。
- **Windows 容器**：只有当其 Windows 版本和行为与目标任务相符时才使用；不能默认视作桌面 Windows 的等价环境。

任务范围扩大后，再投入 VM 快照、环境池和并行调度。首版不需要复制 Terminal-Bench 的完整容器编排系统。

## 建议的最小目录结构

```text
PowerShellBench/
├── README.md
├── tasks/
│   ├── task001/
│   │   ├── README.md
│   │   ├── task.json
│   │   ├── instruction.md
│   │   ├── setup.ps1
│   │   ├── check.ps1
│   │   ├── reference.ps1
│   │   └── fixtures/
│   ├── task002/
│   └── task003/
└── runner/
    └── Invoke-Benchmark.ps1
```

- `README.md`：项目目标、评测边界和如何运行任务。
- `tasks/`：一题一个目录，初始数据、题目和检查逻辑放在一起。
- `task.json`：任务 ID、类别、PowerShell 版本要求、超时和标签等元数据，使用 PowerShell 原生 JSON 解析。
- `instruction.md`：提供给模型的任务描述，不包含答案或隐藏评分细节。
- `setup.ps1`：创建任务所需的初始工作区状态。
- `check.ps1`：在任务结束后检查结果，输出机器可读的评分数据。
- `reference.ps1`：人工参考操作，用于验证任务本身和 checker 可以通过。
- `fixtures/`：任务输入文件，例如日志、CSV、JSON 和中文文件名样本。
- `runner/Invoke-Benchmark.ps1`：runner 占位，后续统一创建工作区、调用执行后端、记录过程并启动评分。

首版暂不需要单独的 leaderboard、复杂插件系统、贡献者审批流水线或多种环境后端。等任务数量和运行方式稳定后，再考虑增加。

## 任务设计检查表

每道题至少应说明或固定：

- 模型看到的用户请求和可用上下文。
- Windows 和 PowerShell 版本、当前目录、区域设置及编码相关条件。
- 任务开始时存在的文件、数据和目录。
- 允许的操作范围，以及不可破坏的数据。
- 成功时必须满足的最终状态。
- checker 如何检查正确性、安全性和副作用。
- 参考解法是否能在新工作区稳定通过。
- 运行日志如何保存，失败能否复现。

对安全敏感或可能破坏数据的任务，应明确模型是否可以直接执行，还是只能生成命令供用户确认。首版建议优先选择结果可验证、影响范围可限制的任务。

## 开放的设计问题

以下事项尚未定案，适合通过小规模原型验证：

- 首版只测 PowerShell 7，还是同时覆盖 Windows PowerShell 5.1。
- 被测对象是一次性命令生成，还是允许模型看到终端反馈并多轮修复。
- 中文乱码和编码兼容性在总体任务中的占比。
- 命令能否使用 Python、Git 或其他预装工具，如何控制工具环境。
- 首批任务类别和数量，以及是否需要公开排行榜。
- 如何在工作区隔离下可靠记录和限制越界副作用。

## 项目定位（一句话）

**PowerShellBench：基于真实 Windows 办公场景，评测大模型使用 PowerShell 安全、可靠地完成终端任务的能力。**
