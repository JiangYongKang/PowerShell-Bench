在编写 Markdown 文档时确保内容简洁并清晰可读，不要滥用 Markdown 标记，标记应该只服务于内容和结构而不是用于装饰。能用一个段落说清的内容，不拆成标题、列表或表格。每个 Markdown 标记都应有必要理由。不确定是否必要时就不用。原始文本尽量保证自然可读，避免大量符号打断阅读。除非用户明确要求，不生成徽章、emoji、分隔线、任务列表、目录、引用块装饰。

# 文档结构

1. 开头用一两句话说明文档目的或适用范围，不写空泛背景。
2. 按读者需要组织内容，先结论后细节，或按操作顺序展开。
3. 长文档才考虑目录，短文档不加目录。

# 文字风格

1. 使用简洁、直接、容易理解的中文，表达准确，可口语化。
2. 一段表达一个主要意思，能一句说清就不拆成列表。
3. 中文使用中文标点；中英文之间、数字与单位之间的空格风格保持一致。

# 标签的使用

1. 默认只使用必要的标题、段落、列表、代码、链接。
2. 少用加粗和斜体。只对关键结论、风险、必读项少量加粗。
3. 不用删除线、分隔线、引用块做普通强调或视觉分隔。
4. 列表只用于并列条目或操作步骤。连续叙述、解释说明、因果分析用段落。
5. 列表项尽量完整、简短。嵌套列表最多 2 层。
6. 不把每句话都拆成列表。列表过多时，改回段落。

# 标题的使用

1. 按内容实际层级选择标题，不跳级，不为形式增加标题。
2. 标题应简短并概括内容。
3. 层级尽量浅，不要添加太多层级结构。
4. 同一文档内编号风格保持一致，不混用多种编号。

# 表格的使用

1. 表格只适合并列比较、整理字段或对照参数。
2. 不要为了避免段落而滥用表格，也不要用表格写长句或大段说明。
3. 表格列数尽量少，表头明确，单元格内容简短。

# 代码块的使用

1. 代码、命令、配置片段较长时使用代码块。
2. 文件名、函数名、命令名、字段名等短标识可用行内代码。
3. 代码块尽量标注语言，代码示例与正文之间留一个空行。
4. 示例代码只保留理解所需内容，省略无关部分时可加简短说明。

# 空行与排版

1. 标题、段落、列表、表格、代码块之间用空行分隔。但不能连续使用多个空行。
2. 不强制手动换行来制造排版效果，让段落自然流动。
3. 确保原始文件即使不渲染，也应能看出标题、段落、列表和代码的边界。
